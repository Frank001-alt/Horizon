hackernews · TangerineDream · Aug 27, 17:17 · [Discussion](https://news.ycombinator.com/item?id=49468083)

**「Background」** Cloudflare&\#x27;s 1.1.1.1 DNS resolver handles massive global traffic, and its cache consumed enormous amounts of memory. As the service grew, the cost and scalability of this memory footprint became a pressing concern, prompting engineers to find ways to reduce it without sacrificing performance.

**「Solution」** The engineers systematically shrank the size of each cache entry by using packed structs, reordering fields to minimize padding, and eliminating unnecessary allocations—such as storing record data inline rather than separately. They also consolidated multiple lists into a single structure, which reduced overhead but required careful handling to maintain safety. These changes, combined with other micro-optimizations, cut memory usage dramatically: the cache went from using over 100 terabytes to a fraction of that, with negligible impact on lookup speed. The article details the tradeoffs, including the complexity of managing packed data and the need to balance memory savings against CPU costs, and provides concrete measurements that validate the approach.

**「Takeaway」** The author demonstrates that significant memory savings in high-performance caching systems are achievable through careful data layout and allocation strategies, and that such optimizations are both practical and valuable even after a product is stable and profitable.

### [GPU Memory Reads: Coalescing and Latency Hiding](https://blog.doubleword.ai/what-happens-when-a-gpu-reads-memory) ⭐️ 8.0/10

rss · Lobsters · Aug 27, 14:42

**「Background」** When a GPU reads memory, the process is far more complex than a simple fetch, involving a hierarchy of caches and memory types. The author explains that understanding this hierarchy is crucial for performance, as naive memory access patterns can severely bottleneck GPU throughput.

**「Solution」** The article breaks down the GPU memory hierarchy, from registers and shared memory to L1/L2 caches and global memory, explaining how each level&\#x27;s latency and bandwidth differ. A key insight is memory coalescing: when threads in a warp access consecutive addresses, the hardware combines these into fewer memory transactions, maximizing bandwidth utilization. The author illustrates this with examples of coalesced versus strided access patterns, showing how the latter wastes bandwidth. Another central mechanism is latency hiding: GPUs hide memory latency by rapidly switching between warps, keeping the execution units busy while some warps wait for memory. The article includes diagrams and concrete numbers to demonstrate these concepts, and discusses tradeoffs such as the limited capacity of shared memory and the need to balance occupancy with resource usage. It also touches on advanced topics like memory alignment and the impact of access patterns on cache behavior.

**「Takeaway」** The author&\#x27;s core thesis is that efficient GPU memory access is not automatic but requires deliberate programming to exploit coalescing and latency hiding. By understanding the memory hierarchy and access patterns, developers can significantly improve performance, making this knowledge essential for GPU optimization.
