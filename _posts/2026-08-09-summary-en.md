Researchers report the first generative design of viable bacteriophage genomes using the genome language models Evo 1 and Evo 2. Using the lytic phage ΦX174 as a template, the models generated whole-genome sequences with realistic genetic architectures and desirable host tropism. Experimental testing of these AI-generated genomes yielded 16 viable phages with substantial evolutionary novelty. This work demonstrates that genome language models can produce functional sequences at the scale of whole genomes, marking a significant milestone for AI-driven biological design and synthetic biology.

**「Background」** Genome language models are AI systems trained on large collections of DNA sequences to learn the patterns and rules of genomes. Evo 2, an expanded successor, was released in 2025. These models can generate novel DNA sequences, but prior to this work, their ability to produce functional sequences at the scale of entire genomes had not been demonstrated.

**「Impact」** This breakthrough enables the design of functional bacteriophages at the whole-genome scale, potentially accelerating synthetic biology applications such as phage therapy and targeted bacterial control, while also opening new avenues for AI-driven genome engineering.

**「Background」** Zsh users often rely on shell history to recall past commands, but a subtle bug can cause history data loss when multiple shell sessions write to the same history file concurrently. The author encountered this issue and set out to diagnose why commands were disappearing from history.

**「Solution」** The author traced the problem to Zsh&\#x27;s history file locking mechanism. When multiple Zsh processes write to the history file, they use file locks to coordinate access. However, the bug arises because Zsh truncates the history file before acquiring the lock, or due to a race condition where one process truncates the file while another is writing, leading to data loss. Through systematic debugging, including strace and examining Zsh&\#x27;s source code, the author identified the exact sequence of operations that causes the truncation. The post also discusses practical mitigations, such as using a single history file per session or adjusting lock settings, though the author notes that a complete fix may require a patch to Zsh itself.

**「Takeaway」** The author&\#x27;s investigation reveals that even mature tools like Zsh can have subtle concurrency bugs that lead to data loss, and understanding the underlying locking and file I/O mechanisms is key to diagnosing and mitigating such issues.
