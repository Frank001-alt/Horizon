### [.NET 11 Runtime Async: 19.6x Faster, Zero Allocations](https://www.v2ex.com/t/1232838#reply2) ⭐️ 8.0/10

A developer benchmarked .NET 11&\#x27;s new runtime async implementation against .NET 10&\#x27;s compiler-generated state machines, reporting dramatic performance gains. Non-yielding async code ran 19.6x faster with zero allocations, awaiting completed tasks was 12x faster with zero allocations, Task.Yield was 7x faster, ThreadPool continuations were 3.2x faster, and async state machine chains were 7.4x faster with 36% less memory allocation. Runtime async moves code generation from the C\# compiler to the runtime, requiring only recompilation, not code changes, and remains a stackless coroutine approach. These results were achieved without full support for inlining and PGO, suggesting further improvements are possible.

rss · V2EX · Aug 7, 17:59

**「Background」** In .NET, async methods are traditionally compiled by the C\# compiler into state machines, which introduce overhead in terms of allocations and slower execution. .NET 11 introduces &\#x27;runtime async&\#x27;, a new runtime-level infrastructure that handles async methods directly, aiming to improve performance and tooling. This feature is part of the .NET 11 preview releases, with ongoing optimizations being merged into the main branch.

**「Impact」** For .NET developers, this could significantly reduce async overhead in high-throughput applications, making async code nearly as fast as synchronous code in common scenarios, with potential for further gains as optimizations mature.

### [Linux KVM 曝出虚拟机逃逸漏洞，嵌套虚拟化成攻击突破口](https://www.ithome.com/0/987/212.htm) ⭐️ 8.0/10

A newly disclosed Linux KVM vulnerability, named Zapscape and tracked as CVE-2026-64561, allows virtual machine escape and host kernel code execution. The flaw resides in a use-after-free \(UAF\) in the KVM/x86 Shadow MMU, specifically in the recursive zap path of Shadow Pages. An attacker can trigger it using only guest operations, corrupting the host kernel&\#x27;s Shadow Page. This affects public cloud platforms and environments with nested virtualization enabled, potentially allowing an attacker to crash the host kernel, impact other VMs on the same server, and execute code with root privileges on the host, thereby controlling the host and all guest machines. The vulnerability was reported by developer Hyunwoo Kim on GitHub, with a reference repository available.

rss · IT HOME · Aug 7, 14:42

**「Background」** KVM \(Kernel-based Virtual Machine\) is a Linux kernel module that provides hardware-assisted virtualization for x86 processors, allowing multiple virtual machines \(guests\) to run on a single host. The Shadow MMU is a component of KVM that manages shadow page tables, which are used to translate guest virtual addresses to host physical addresses. A use-after-free \(UAF\) vulnerability occurs when a program continues to reference memory after it has been freed, potentially leading to memory corruption or arbitrary code execution. The Zapscape vulnerability \(CVE-2026-64561\) is a UAF in the Shadow MMU&\#x27;s recursive zap path, which is triggered when shadow pages are reclaimed.

**「Impact」** Users of public cloud VM instances and nested virtualization environments are at risk of host compromise, including kernel crashes and root-level code execution, which could lead to full control of the host and all co-resident VMs. The severity is high, though the exploit requires guest-level access and the vulnerability&\#x27;s practical exploitation in the wild has not been confirmed.
